**默认 API 后端的校园网认证闭环，以及增强版切换中国移动，均已通过真实网络验证。** 最终保持中国移动在线，外网 HTTPS 正常。此次还修复了在线服务误判、业务错误识别和并发配置覆盖问题，并新增显式切换与失败恢复；未触发分支和可选能力的验证范围见后文。

## DNS 故障与修复

原网卡 `eno1` 配置的 DNS 为 `202.206.40.12`、`8.8.4.4`，两者从原主机查询均超时。直接查询 `202.206.240.12`、`202.206.240.13` 均成功；使用已验证地址 `222.30.148.40` 绕过 DNS 访问同一 HTTPS 门户成功返回 `302`，TLS 校验保持开启。

因此当前阻塞定位为不可用的 DNS 配置。首选地址高度疑似将 `202.206.240.12` 写成了 `202.206.40.12`，备用 DNS 又未能响应。过程中曾在另一台校内服务器对照测试，但最终修复和认证验收均回到原主机执行。

用户在远端终端自行完成 `sudo -v` 后，执行以下修复：

- 将原 Netplan 配置和运行时 DNS 备份到远端 `/var/backups/ysu-net-dns.iaYtUO/`，备份仅管理员可读。
- 持久化配置来源为 `/etc/netplan/99-static-eno1.yaml`；DNS 改为 `202.206.240.12`、`202.206.240.13`。
- 通过 `netplan generate` 验证并生成配置，再用 `resolvectl dns eno1 ...` 更新运行时解析器并刷新缓存；没有重启网卡或执行全网卡 `netplan apply`。
- 发现 `netplan set` 首次设置数组时合并了旧地址，随后先将 DNS 地址字段设为 `null`，再设置新列表，最终确认旧地址全部移除。
- 对备份与现配置做 YAML 语义比较：仅 nameservers 改变，静态 IP、默认网关及 DHCP 设置不变。

修复后，系统解析门户和统一认证域名均成功；持久化 DNS 与运行时 DNS 一致。未重启服务器，因此“重启后恢复”仅完成配置检查，不列为重启实测。

### 回滚位置

如确需撤销本次 DNS 修改，可由管理员使用备份中的 `netplan/99-static-eno1.yaml` 恢复对应文件，然后生成配置并恢复备份中的运行时 DNS。原 DNS 已实测超时，回滚会重新引入该问题；恢复前应确认配置未被其他维护者继续修改。

## 中国移动后续测试与能力增强

用户明确同意测试中国移动后，在原主机使用同一测试账号执行：

1. 校园网在线时直接请求中国移动登录，旧实现返回 0，但独立查询仍显示“校园网”，确认服务校验缺失。
2. 确认账号一致后真实下线，独立 status=1，再请求中国移动登录；返回 3，未上线。
3. 追加一次脱敏协议诊断：`serviceLogin`、`userOnline` HTTP 均为 200，后者含布尔类型 `data.online` 与明确的“你使用的账号已达到同时在线用户数量上限”消息，随后 status=1。该次脱敏输出未保留布尔值本身；新版 `online=false` 错误分支通过模拟测试验证，最终实测未再触发上限。旧实现只报告登录超时。
4. 每次失败后均重新登录校园网，独立确认在线。没有主动断开该账号的其他终端。

基于上述证据完成以下增强：

- API 与浏览器登录均校验实际在线服务，阻止错误服务返回成功；缺失或矛盾的服务信息按未知处理。
- 识别 HTTP 成功内的明确认证失败；会话数上限、已识别的密码/验证码问题返回 4，守护暂停该配置重试。没有明确错误的异步 `online=false` 仍允许后续轮询。
- 新增 `ysu switch <服务名>`，验证账号、实际服务、下线状态和目标连接；失败时尝试恢复真实原服务。恢复结果单独报告，不把回滚成功当作切换成功。
- 子进程错误只转换为固定白名单诊断，包括 DNS、TLS、服务不匹配与会话数上限；不转发原始错误内的账号或 IP。
- 切换成功后仅合并服务字段；配置更新使用独立短时写锁，避免覆盖网络操作期间更新的密码，同时保留守护配置热更新。

离线回归新增覆盖失败恢复、未知状态、其他账号保护、配置并发、环境凭据不落盘、协议错误及双后端服务校验。

## 复测要求

默认单元测试始终禁止联网。真实测试应在目标校内主机执行，并先确认 DNS 与门户连接；不要将代理 Fake-IP 写入 hosts。

使用交互方式输入凭据，先确认离线，再验证登录、独立状态查询与账户查询。已在线时 login 的成功返回仅证明幂等，不证明新凭据有效。执行下线前确认在线账号属于测试账号，并准备独立于 SSH 的恢复路径。测试结束应保持期望连接状态，清理临时进程和源码副本，保留脱敏验收证据及必要的配置回滚备份。
