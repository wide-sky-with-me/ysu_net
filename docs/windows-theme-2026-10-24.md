## 改动及原因

旧松石青选项覆盖了背景、卡片、输入框、文字和边框的整套表面，而非仅强调色；本机仍保存该选择，因此虽然代码默认 `blue`，暗色仍呈墨绿色。现在六色共用灰白/灰黑表面，主题色只用于控件和小面积强调，流量卡不再整体染色。默认仍为蓝色；产品不清空或迁移其他用户的合法偏好。本机按用户要求单独将 `accent` 从 `teal` 切至 `blue`，保留 `theme=system` 及其他设置。

文字、按钮和焦点对比一并调整；在线绿、离线红、未知警告色继续独立于主题色。实现和现行色值仅维护在[设计说明](rust-desktop-design.md)。

## 卸载、数据保护与安装后状态

核对原安装路径、注册项、正式旧二进制及新安装包哈希后，创建仅当前用户和 SYSTEM 可访问的保护备份。共备份并检查 **226 个文件**，包含账号配置及应用用户数据。通过无清理数据参数的 NSIS 静默卸载，再安装本地新包；安装前后全部原文件先逐字节校验，未需恢复缺失文件。之后仅原子修改外观文件的 `accent`，其他字段按值验证相同。

保护备份保留在 Windows 用户本地数据下的 `ysu-net-ui-reinstall/run-20261024-220910/backup`，不复制私人内容到仓库。桌面及开始菜单快捷方式指向正常安装 EXE，参数为空；系统自启状态未改变。安装器和离线测试使用进程级 Demo/空账号配置与隔离 WebView 目录，不修改持久环境变量。未执行真实登录、下线、运营商或账号切换。

正常客户端未代替用户自动启动。原生测试与临时回环调试监听均已退出；原先由其他工作保留的 1422 预览未触碰。

## 失败与复测

- 新增配色契约最初使用 Node 文件类型，前端类型检查拒绝；改为 Vite `?raw` 后又遇到 Vitest 默认 CSS 空字符串替身。按官方配置启用这两个 CSS 文件的处理，保留全部断言，162 项通过；未添加新依赖。
- 依赖准备先因专用 D 盘父目录尚未创建而停止，未运行安装/应用。创建已核对的父目录后依赖命令均成功；Cargo fetch 生成 `.rustc_info.json`，被过严的“目标必须完全为空”后置条件拒绝。单独核实仅存在该元数据且所有锁文件/命令成功，保留失败记录后准入，不删除目录或伪造构建结果。
- 浏览器服务器助手一次启动超时；改用受管理的直接 Vite 进程，在确认 URL 后完成四条回归，并停止该进程。
- 本机助手第一次在卸载前因不存在的自启注册值查询停止；改用返回空值的 Registry API。下一次已卸载并安装成功，但 PowerShell/.NET 的空备份路径导致外观原子替换停止。核对新载荷和所有原用户文件未变后，仅从外观阶段续跑，改用受保护的显式备份路径，未重复卸载。
- 原生颜色探针首次受 PowerShell 的 `VoidTaskResult` 管道输出影响，在允许截图前停止并清理自有进程。抑制该测试适配器输出后，重新确认 Demo，再完成明暗探测、截图、正常退出及用户文件复核。
