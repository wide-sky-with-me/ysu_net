# 敏感信息与发布检查

## 资料边界

真实账号和密码只保存在仓库外的用户配置中：配置文件权限为 `0600`，新建专用目录为 `0700`。优先使用 `ysu config account` 交互录入；不要把凭据放进命令参数、代码、测试、截图或提交说明。

`ysu config show` 会隐藏密码。普通账户展示不输出 `userIndex` 或账户条目的签名链接，但仍含用户主动查询的姓名、账号和 IP；它不是匿名报告。`status/info --raw` 保留原始响应，可能带有会话标识及账户数据，分享前须脱敏。

后台输出固定分类的错误提示，不直接转发认证进程的原始错误。管理入口禁用认证调试文件；直接调用底层后端时，显式启用调试或文件保存可能暴露 Cookie、认证请求与页面内容。诊断文件只留在受控本地目录，不上传工单或公开仓库。验证码图片也应作为临时认证资料处理。

## 防止误提交

`.gitignore` 覆盖真实配置及其锁文件、`.env` 及环境变体、Cookie、认证页面/请求、验证码、密钥容器、HAR、日志、虚拟环境和构建输出。`.env.example`、`.env.sample` 可提交，但只能使用明确的占位内容。

忽略规则不影响已经跟踪的文件，也不能识别嵌入源码的秘密。新增文件、强制添加文件和发布包都需要单独检查。测试中的虚构账号、简单密码和无效 URL 用于验证配置与脱敏行为，不可替换为真实值。

## 发布前检查

```bash
git status --short --ignored=matching
git diff --check
git diff --cached --check
uv run --extra browser python -m unittest discover -s tests -q
bash -n install.sh uninstall.sh
uv lock --check
uv build
```

检查当前文件、待提交 diff 和可达 Git 历史中的凭据特征；扫描报告只保留规则、路径、行号或对象哈希，不回显匹配值。人工复核命中，区分协议常量、公共门户地址、测试数据和真实凭据。再检查 wheel 与源码包的成员及内容，确认没有配置、会话资料、私钥或临时调试文件。

提交后确认 `git status --porcelain` 为空，本地 `HEAD` 与远端分支一致。忽略的虚拟环境和发布包可以保留，不为清理工作区而删除用户配置或运行环境。

若发现真实凭据，应先撤销或轮换，再评估当前文件和历史的处理范围；删除当前文件不等于清除 Git 历史。历史改写和强推需要单独协调，不能替代凭据轮换。
