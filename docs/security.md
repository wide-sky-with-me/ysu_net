# 敏感信息与发布检查

[返回首页](../README.md) · [开发与验证](development.md) · [使用说明](usage.md)

## 资料边界

真实账号和密码只保存在仓库外的用户配置中：配置文件权限为 `0600`，新建专用目录为 `0700`。优先使用 `ysu config account` 交互录入；不要把凭据放进命令参数、代码、测试、截图或提交说明。

`ysu config show` 会隐藏密码。普通账户展示不输出 `userIndex` 或账户条目的签名链接，但仍含用户主动查询的姓名、账号和 IP；它不是匿名报告。`status/info --raw` 保留原始响应，可能带有会话标识及账户数据，分享前须脱敏。

后台输出固定分类的错误提示，不直接转发认证进程的原始错误。管理入口禁用认证调试文件；直接调用底层后端时，显式启用调试或文件保存可能暴露 Cookie、认证请求与页面内容。诊断文件只留在受控本地目录，不上传工单或公开仓库。验证码图片也应作为临时认证资料处理。

## 公开反馈的脱敏清单

Issue、Discussion、PR、Wiki、发布说明和附件均属于公开资料。投稿前只保留复现所需的系统版本、工具版本、认证方式、运营商、操作步骤和状态/错误类型，并完成以下检查：

- 将姓名、账号/学号、邮箱、电话、位置、IP、MAC、设备名称及用户目录替换成明确占位值；同一对象可用 `<ACCOUNT_A>`、`<DEVICE_A>` 标识，保持复现关系。
- 移除密码、Cookie、Authorization、Token、`userIndex`、会话、签名链接及其查询参数；不要上传配置文件、环境变量转储、HAR、认证请求/响应、页面或验证码。
- 日志只节选必要的固定状态和错误提示，删除含个人路径、账号、设备或会话的行；`status/info --raw` 与底层 `--debug` 输出不适合直接公开。
- 截图先裁剪到故障区域，用不透明遮盖移除识别信息，再导出一张新的平面图片；检查浏览器地址栏、终端提示符、通知、其他窗口及图片元数据。不要依赖可逆遮挡或轻度模糊。
- 提交前逐项检查正文、标题、附件文件名、截图和提交说明；表单中的确认框不自动执行脱敏，规则扫描也不能识别全部秘密。

脱敏示例（只展示字段关系，不是真实输出）：

```text
版本：v0.1.0-beta.1
系统：Windows 11 x64
认证：API；服务：校园网
现象：自动重连后网络恢复，界面仍显示未连接；手动刷新后显示已连接
账号：<ACCOUNT>；设备：<DEVICE>；地址：<IP>；路径：<USER_HOME>/ysu-net
日志：<仅保留已人工检查的状态/错误片段>
```

表单不要求填写这些识别字段；占位示例仅说明已有材料的替换方式。疑似秘密已公开时优先轮换凭据并终止相关会话，再通过 [私密报告入口](https://github.com/wide-sky-with-me/ysu_net/security/advisories/new) 提供定位链接。删除正文不等于清除历史、通知和缓存。更多处理约定见 [SECURITY.md](../SECURITY.md)。

## 防止误提交

`.gitignore` 覆盖真实配置及其锁文件、`.env` 及环境变体、Cookie、认证页面/请求、验证码、密钥容器、HAR、日志、虚拟环境和构建输出。`.env.example`、`.env.sample` 可提交，但只能使用明确的占位内容。

忽略规则不影响已经跟踪的文件，也不能识别嵌入源码的秘密。新增文件、强制添加文件和发布包都需要单独检查。测试中的虚构账号、简单密码和无效 URL 用于验证配置与脱敏行为，不可替换为真实值。

## 发布前检查

本机只做文档、diff 与敏感资料的静态核对；构建、产品测试及包内容检查仅在 GitHub Actions runner 执行。本机不为发布检查准备构建 SDK、启动 preview 或补做编译，只下载、校验云端产物并安装或运行。

```bash
# 本机允许的静态核对：
git status --short --ignored=matching
git diff --check
git diff --cached --check
```

以下为 GitHub Actions runner 专用示例，不在本机执行：

```bash
# 仅在 GitHub Actions runner 执行：
uv run --extra browser python -m unittest discover -s tests -q
bash -n install.sh uninstall.sh
uv lock --check
uv build
```

检查当前文件、待提交 diff 和可达 Git 历史中的凭据特征；扫描报告只保留规则、路径、行号或对象哈希，不回显匹配值。人工复核命中，区分协议常量、公共门户地址、测试数据和真实凭据。云端构建后在 runner 检查 wheel 与源码包的成员及内容，确认没有配置、会话资料、私钥或临时调试文件；本机核对下载来源与云端校验和，不重新构建。

提交后确认 `git status --porcelain` 为空，本地 `HEAD` 与远端分支一致。忽略的虚拟环境和发布包可以保留，不为清理工作区而删除用户配置或运行环境。

若发现真实凭据，应先撤销或轮换，再评估当前文件和历史的处理范围；删除当前文件不等于清除 Git 历史。历史改写和强推需要单独协调，不能替代凭据轮换。
