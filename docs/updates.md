## 使用与版本边界

当前正式版本统一见[首页发行状态](../README.md#发行与候选状态)。自 0.2.2 起，更新入口集中在侧栏“关于”，客户端支持条件差分；0.2.1 的入口在“设置 → 外观与启动”底部且仅支持整包。0.2.3 的[公开资产记录](desktop-release-0.2.3.md#公开资产与签名)确认当次仅有 13 项完整资产、`deltaTargets` 为空，没有差分附件或生产补丁签名。旧版本与信任锚迁移见[迁移说明](migration.md)。差分能力与云端夹具通过不等于真实省流量、原位升级或失败回滚已验收。

仅用户点击“检查更新”才访问版本源。发现新版后展示版本与纯文本说明，用户确认后才下载、验签并安装；没有启动时自动下载或静默强制升级。Demo / 普通网页不检查或安装真实更新；前端不能指定下载地址或公钥。差分只优化传输，不改变确认与安装方式。

- Windows x64：完整载荷仍为当前用户 NSIS 安装器，安装器可能直接退出旧进程。
- macOS arm64 / x64：完整载荷仍为对应架构 `.app.tar.gz`；安装后按界面提示重启。当前未提供 Apple 发布者签名 / 公证，更新签名不替代它们。
- Linux `.deb`：继续通过固定 Releases 入口下载并按系统包升级，不启用原位安装或差分目标。Python CLI 的安装 / 升级方式不变。

“前往发布页”在原生客户端通过无参数 `updater_open_releases` 调用官方 opener 的 Rust API，只能打开内置固定 Releases 地址；不开放任意 URL、应用程序选择或插件 guest 权限。普通网页使用正常链接，Demo 不显示或调用真实打开入口。Linux deb 声明 `xdg-utils` 运行依赖，默认浏览器须由系统正确配置；成功分派不代表网页已加载。失败显示固定错误及可复制的公共地址，不输出本机路径或底层异常。

## 差分传输与一次回退

自 0.2.2 起，差分实现使用 BSDIFF40 / qbsdiff 1.4.4，对完整安装器或 app archive 还原字节，不修补运行中的程序、安装目录或已安装文件。旧 `version / platforms / url / signature` 与三个完整平台条目保留；可选顶层 `deltas` 只是扩展，旧客户端仍下载相同整包。每次实际附件归对应发行记录；[0.2.3 本次清单](desktop-release-0.2.3.md#公开资产与签名)没有差分附件，不把支持能力或空门禁说成已执行生产补丁链。

只有当前版本、完整平台 / 架构 / 包类型、缓存基线的大小与 SHA256 全部精确匹配，且扩展中的整包 URL / 签名与官方 SDK 选中的完整候选一致时，才选择差分。补丁必须小于完整包的 80%。无缓存的首次更新直接下载新整包，不从运行文件拼基线，也不先下载旧整包来凑差分；扩展未知、损坏或不兼容时忽略扩展，保留正常整包路径。差分不保证每次都有收益。

补丁先由官方 `Update::verify` 使用客户端原公钥及目标受签名版本验证，之后才预审和解码；还原结果还必须通过原完整包的官方签名 / 版本验证，才能交给原安装生命周期，官方 `install` 仍再次验证。SHA256 和大小只用于选择与完整性核对，不是信任根；补丁不能另带任意公钥。签名绑定载荷与版本，不单独证明架构，平台键、包类型及精确 URL / 签名配对仍须同时成立。

已选差分的下载、补丁验签、预审、还原或还原整包验签失败时，最多回退一次原候选整包下载，并重新执行原整包官方验签。回退使用完整包自身上限，不以不可信扩展中的目标摘要 / 长度阻断本来有效的完整候选。回退只发生在下载阶段返回已验证完整字节之前；安装或后台恢复失败绝不触发再次下载、第二次安装。界面区分差分下载、还原完整包与回退整包，切换传输时重置下载进度，不把还原进度当已安装。

## 缓存与资源边界

缓存只在用户确认后的下载路径使用，位于系统应用缓存目录的固定 `update-packages-v1` 子目录，不使用账号配置目录。文件名由白名单完整平台 / 包类型、版本和摘要构造，不混用 Windows NSIS 与两种 macOS 架构。已验证目标在进入可能退出进程的 Windows 安装前写入缓存，供后续版本匹配基线；缓存不保证存在，不能据此承诺首更省流量。

整个下载持有缓存独占锁，缓存所有者销毁时显式解锁，不让 Unix fork / exec 窗口中的继承描述符延长占用，取舍见[锁生命周期决策](../.agents/notes/implemented/desktop/2026-10-28-cache-lock-lifetime.md)。基线按同一个已打开对象读取、哈希和使用，拒绝链接、Windows reparse point 和非普通文件。Unix 文件操作锚定目录句柄，Windows 保留禁止删除共享的父目录句柄。目标使用同目录独占临时文件完整写入、同步后无覆盖原子提交；清理只处理本模块命名且未被占用的条目，保留本轮使用的精确基线，不扫描用户文件。缓存无法打开、被占用、维护或基线读取失败时跳过差分，走正常整包路径；已验签目标写入失败只是不缓存，不阻止安装。

实现最多保留两个整包，每份不超过 64 MiB；写入前先腾至最多一份，含暂存写入的缓存包数据峰值预算不超过 128 MiB，不包括官方安装器自身的临时目录。这是实现的资源限制，不是磁盘占用实测成绩。清单实际读取最多 1 MiB、补丁最多 32 MiB、整包 / 基线最多 64 MiB；不能仅信任 `Content-Length`。

下载初始地址限定本仓库 HTTPS Release 附件，最多五次重定向，每跳只接受 HTTPS 的 GitHub 与明确的官方 Release CDN 域；不转发应用认证信息、SDK 自定义认证头或 Cookie，不把签名重定向地址和原始网络异常返回界面。系统代理兼容不等于放宽地址、验签或错误脱敏约束。

补丁在解码前检查 BSDIFF40 长度、checked 算术、控制记录 / 连续零进展、来源区间与总输出，并流式预审压缩段；当前控制记录最多 100,000 条，连续零进展最多 1,024 条。还原使用字节预算与合作式 deadline，不宣称可以强制杀死阻塞线程或保证硬 CPU 超时，也不以异常捕获替代恶意输入预防。

## 安装与后台生命周期

检查、下载或验签失败不会停止认证后台。完整字节验证后若认证工作正在执行，安装被阻止；暂停准入同时拦住新任务、排队任务、启动首查与自动重连。暂停不发 Portal 下线请求，不改变账号、自动重连偏好或系统自启。仅暂停 / 安装 / 后台重建临界段暂缓普通退出，下载阶段仍可退出。

Windows 官方安装器成功后自行退出，不用其提前执行的回调不可逆地丢弃恢复上下文。安装失败沿原路径尝试恢复同配置后台；恢复失败保持锁定，只能显式重试恢复或退出重开，不在半停机状态自动认证，也不借差分回退二次安装。重启参数沿用启动时已解析的绝对配置路径，避免安装器或 LaunchServices 改变工作目录后读错配置。

更新源没有 `latest.json` 时显示“更新源尚未就绪”，不是“已经是最新版”。网络、清单、签名、安装和后台恢复使用固定错误，不输出含下载令牌的底层异常。

## 信任与云端发布

使用[官方 Tauri updater](https://v2.tauri.app/plugin/updater/)，不自实现密码学。公钥内嵌于 [Tauri 配置](../desktop/src-tauri/tauri.conf.json)，私钥不进入客户端、源码、日志或附件。`requireSignedVersion=true` 绑定已签载荷与公告版本，拒绝用更高公告版本重放旧签名。0.2.1 首次正式更新发行按[信任锚决策](../.agents/notes/implemented/desktop/2026-10-24-first-signed-release-trust-anchor.md)建立基线；**0.2.2 / 0.2.3 沿用该正式公钥，不换信任锚**。此前使用旧公钥的候选仍须[手动安装正式版](migration.md#桌面-v021-及旧候选包)，不能关闭验签或改公钥绕过；未来换钥须另行设计迁移。

版本源固定为 `https://github.com/wide-sky-with-me/ysu_net/releases/latest/download/latest.json`。完整包与补丁均只接受本仓库规范 Release 附件，清单内联各自 `.sig` 内容。Windows x64、macOS x64 / arm64 维持完整平台选择，Linux deb 不伪造自动更新目标。

依赖锁文件解析、测试夹具生成、编译、测试与打包均在 GitHub Actions 执行，不回退本机编译。开发构建使用独立构建分支，不打版本标签、不发布正式 Release，也不配置或读取生产私钥。本机只按授权下载、校验云端产物及做安装 / 运行验收；流程与实际发行状态见[云端构建说明](tauri-desktop.md#构建前提)和[首页](../README.md#发行与候选状态)。

[整包发布工具](../packaging/tauri_update_manifest.py)保留原 13 项资产与三个完整更新载荷；[差分发布工具](../packaging/tauri_delta.py)仅在有对应可信公开旧基线且收益达标时增加补丁 / 签名对，不移除完整包。未提供基线或某平台无基线、补丁不够小则仍可只发完整包；显式提供的基线、工具或签名无效时失败关闭，不静默发布半成品。

差分发布先使用维护中的 Minisign 与客户端原公钥验证新整包、公开旧基线及各自受签名版本，生成补丁后逐字节还原比对并验证还原整包。在对应正式 tag 的实际补丁签名步骤中，由锁定 Tauri signer 的 `--app-version` 对补丁签名，再以原公钥验证补丁、完整载荷和精确清单；发布端每个目标最多添加一个基线描述符。最终资产清单为原 13 项加已声明补丁 / 签名对，URL、内联签名与 `SHA256SUMS` 都须与实际文件一致。结构或 SHA 校验不替代公钥验签；验证工具缺失、签名或还原失败均阻止发布。

正式 tag 的 Windows / macOS 构建需既有 GitHub Actions 签名 Secret；发布须通过四平台构建、原生 / 安装与独立浏览器验收门槛。普通开发构建不需该私钥。不能用 Tauri CLI 构建 / 签名成功替代原公钥验证，因为 [CLI 2.12.2 的密钥不匹配检查](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.2/crates/tauri-cli/src/bundle.rs)允许只告警后继续签名，也不能从待发布附件下载新公钥替换信任锚。0.2.3 正式流程已用原公钥及受签名版本验证三个真实完整载荷，并取得可信 0.2.2 公开基线；补丁均未达到发布条件，最终只有 13 项完整资产，未调用生产补丁 signer。公开下载字节已与云端已验签资产一致，详见[发布记录](desktop-release-0.2.3.md)；这不等于本机重新验签或真实安装通过。

## 验证范围

[2026-10-26 差分验收记录](desktop-delta-2026-10-26.md)保存对应四平台源码与 run 身份、官方双签及 Linux CLI / Minisign 集成、失败修正与剩余范围。无缓存首更、精确基线 / 平台、无效扩展、预算、缓存链接 / 原子失败和一次回退等有回归覆盖；网络失败与安装恢复仍区分注入网络层、Mock trace 和真实环境。仓库只接收云端独立测试密钥的公开密钥、签名与不可执行载荷，不含私钥。

后续 TLS provider 初始化修复及 0.2.2 发行证据见[该版发布记录](desktop-release-0.2.2.md)与[随包版本日志](../packaging/release-notes.md#ysu-net-v022)。0.2.3 增加缓存所有者显式解锁及 Unix 描述符继承回归；当次失败、修复和最终四平台结果见[0.2.3 记录](desktop-release-0.2.3.md)，不以早期候选替代最终产物证据。

既有单元测试覆盖状态机、认证门闩、失败恢复及官方 `Update::verify` 的有效签名、损坏载荷、伪造版本和坏签名断言。发布页测试通过真实 IPC 路由及 Linux 隔离记录脚本核对固定地址，不代表系统浏览器页面已经加载；网页 Mock 只验证交互与 IPC。历史成绩只属于其记录的源码与环境，不自动覆盖后续变更。

0.2.3 真实完整包签名、公开附件与固定 Latest 清单已有发布复核；没有生产补丁签名或真实差分省流量成绩。Windows / macOS 软件内跨版本原位升级、失败回滚与系统登录自启仍须逐项验收。共用 Rust 认证库在 21 的真实登录 / 退出另有[独立证据](desktop-release-0.2.3.md#修复后的真实验证)，不代表更新安装链已通过。普通安装、Linux deb 或纯文本差分夹具不能替代这些场景；本页维护当前语义，具体成绩与未覆盖范围见对应验收记录。
