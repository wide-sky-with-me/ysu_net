## 现场证据与改动

用户在另一台 Windows 使用 0.2.0，浏览器门户可用；账号纠正后日志从 code 3 的操作未核验变为 code 2 的查询失败。旧版仅显示公共文案，不足以区分导航、会话和在线结果等阶段。现场 code 2 根因仍待该候选的新固定分类日志确认，不以 Mock / CI 或本机已有在线会话读取冒充新登录验证。

- 固定 `action / phase / code / operation / stage / reason` 分类，不传出任意底层 message、完整 URL、账号或 Cookie。
- Info 后独立 Status，共用一次总预算；只有独立证据确认离线才显示离线。旧 Info-only 在隔离副本被新断言证伪，再由候选通过；不是删除或放宽断言。
- Portal 流程节点外 / 内业务失败后停止，Rust、Python API 和 browser 共享样本；旧实现确实会继续发上线请求，此缺口与现场根因分开记录。
- 用户确认的签名在线更新、版本绑定、固定源、失败恢复与绝对配置重启参数；安装 / 恢复与普通退出有原子准入门闩。首轮候选在交叉审查发现退出竞态后作废，交付包来自修正后重建。
