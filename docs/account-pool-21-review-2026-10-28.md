## 输入与隔离

用户要求先验证 Shell 账号池，再改进 Rust，并提供一个新账号，随后明确其服务为“校园网”。本记录只使用角色 A / B：A 为 21 已验证的原中国移动账号，B 为本次新增校园网账号，不保存真实用户名或密码。

继续采用[21 Shell 对照](portal-21-review-2026-10-28.md)中的正式 v0.2.2 云端 wheel，25 个源码文件校验一致；复用现有解释器及依赖，没有覆盖原客户端。账号创建使用正常 manager.accounts 存储 API；列表、切换、删除保护及守护均使用原 CLI / daemon 入口，没有改写认证或切换结果。

测试创建独立配置和账号簿，目录 `0700`、配置及账号簿 `0600`；这是账号池正常持久化所需的临时凭据文件。新账号经关闭回显的 stdin 及加密 SSH 管道传入，不进入命令参数、原配置、公开日志或本地文件。原用户服务在测试期间暂时停止，避免与隔离配置争用同一网络连接；另起同一正式包的临时前台守护验证控制通道，结束后恢复原服务。

## 实际命令与结果

UTC 03:11:36 至 03:11:55（北京时间 11:11:36 至 11:11:55），使用云端包的 `python -P -m ysu_net --config <隔离配置>` 运行：

| 测试 | 退出码 | 实际结果 |
| --- | --- | --- |
| `accounts list --raw` | 0 | 两个账号可见，密码字段不公开，仅有 password_set |
| 停用 B 后 `accounts switch <B_ID>` | 2 | 正确拒绝；A 保持在线，零网络请求 |
| 空闲直接切换 A → B | 0 | B / 校园网独立核验在线，活动配置才变为 B |
| B 活动时 `accounts delete <B_ID>` | 2 | 正确拒绝；零网络请求 |
| 空闲直接切换 B → A | 0 | A / 移动独立核验在线，活动配置变为 A |
| 临时守护持锁：切换 A → B | 0 | CLI 走私有控制通道，锁所有者串行完成；B / 校园网核验通过 |
| 同上：切换 B → A | 0 | 同一控制通道串行完成；A / 移动核验通过 |
| `accounts rotation off` | 0 | 通过守护控制通道关闭轮换，结束时保持默认关闭 |

四次换号每次都实际观测到：旧账号配置发出一次 offline POST → 明确 offline 响应 → 目标账号发出一次 CAS 密码 POST → 目标身份在线响应 → commit_switch 开始时活动配置仍为源账号 → commit 完成后为目标账号。每次命令结束后另行查询，目标身份及服务均匹配，不能用命令退出码或已在线空操作代替。

两次热切换均同时观测到 CLI 的控制请求和守护的成功 / committed 响应；没有绕过运行锁并发登录。观察器只增加闭集角色、时间戳、阶段以及 commit / IPC 被动记录，保持请求、返回结果和业务逻辑不变；本次是带插桩的真实功能验证。

主流程记录 223 次应用请求尝试、4 次 CAS 密码 POST、4 次实际 offline POST，不是网络抓包计数。禁用候选和删除当前账号两个负例均未发起网络请求。未人为耗尽流量或提交错误密码，因此**真实零流量触发、认证拒绝后的恢复路径尚未实测**，不能从四次成功切换推定它们已通过。

## 对 Rust 的源码补充

Rust Worker 原本已有先下线源账号、核验离线、再登录目标并核验后提交的顺序。源码检查发现，账号切换的 mutate 错误被通用提示覆盖，底层 AuthDiagnostic 未写入日志；其 phase 也未随流程更新，整体超时可能被记为排队阶段。

本轮在[账号运行器](../desktop/src-tauri/src/account_runtime.rs)补齐查询、下线、目标登录、核验、提交及恢复阶段；复用既有固定诊断格式记录下线 / 登录错误，不输出服务器原文或凭据，不放宽状态 / 身份 / 服务条件，也不改变恢复与冷却政策。

[原生回归源码](../desktop/src-tauri/src/account_runtime_tests.rs)新增与本次跨服务换号对应的完整调用序列，阻塞目标核验时证明活动配置仍为 A；目标核验失败时证明不提交 B 并恢复 A；恢复成功后仍可查到原门户跳转失败分类；既有总预算测试同时检查超时阶段。网络采用 Demo 后端，运行实际 Worker 编排，不是 GUI 或真实门户验收。

按用户要求仅保留源码。新增 Rust 测试、格式和编译尚未执行，不能称 Rust 账号池已通过；前述 Shell 成绩也不替代 Rust。无界面认证探针只覆盖 AuthClient，不覆盖 Worker 的账号池编排，验证边界见[探针说明](rust-auth-probe.md)。选择原因归[决策](../.agents/notes/implemented/accounts/2026-10-28-account-switch-validation.md)。
