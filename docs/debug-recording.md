## 复现前后

1. 打开桌面客户端的“日志”页，点击“开始调试记录”。等到显示“正在记录”和文件名，再执行操作。
2. 先用“刷新状态”复现只读查询；需要复现登录、退出或自动重连时，再执行相应操作。开始记录本身不查询网络、不登录、不下线，也不切换账号。
3. 故障发生后，即使已经断网，仍可在“日志”页停止记录并打开记录目录。复制对应 `.jsonl` 文件后再关闭客户端。
4. 程序重启后记录默认关闭，旧文件仍可从记录目录读取；重新开始会生成新文件。

记录不依赖互联网或窗口持续显示。关闭窗口进入托盘时继续记录；正常退出客户端或安装更新停止后台时结束记录。不把“已退出操作”与“已确认下线”混为一谈：退出后的独立状态查询也可能失败。

要采集完整操作，先等待当前任务结束再开启记录。认证请求按创建时绑定的文件记录，不把已有请求改投新文件；桌面随后产生的固定状态 / 错误通知仍按当时的记录窗口保存。

## 文件与范围

文件位于当前配置旁的 `config.diagnostics` 目录；自定义配置按其文件名替换扩展名。使用界面的“打开记录目录”，无需自行填写路径。Unix 新目录 / 文件分别按 `0700` / `0600` 创建，Windows 继承配置父目录的访问权限。

复现时使用本地磁盘目录；如果配置位于网络共享目录，其记录目录仍可能随断网不可写。

每份文件上限 8 MiB，到限写入结束标记并停止，不覆盖当前文件开头。开始新记录时保留最多五份本模块生成的记录，按修改时间清理最旧且未被占用的文件；其他文件不清理。开始前如需长期保留旧记录，先复制到其他位置。

每条事件直接写入并 flush；开始确认及正常停止时执行磁盘同步。写入失败显示错误，认证流程仍按原有规则继续。记录不能补回开启前的事件，异常终止可能缺少最后一行或结束标记，也不保证断电恢复。调试增加本地磁盘 I/O，不延长认证原有超时。

| 内容 | 记录方式 |
| --- | --- |
| 运行身份 | 客户端版本、平台、架构与云端可用时的来源提交，UTC 时间、单调耗时和顺序号 |
| 桌面任务 | 手动操作、自动重连、后台观察和账号切换的固定任务分类 |
| 认证过程 | 操作 ID、关键阶段、成功 / 失败 / 取消及固定诊断 |
| 原生 HTTP | 请求开始、响应状态、响应字节数、完成 / 取消；只有地址角色和形状分类 |
| 网络失败 | 发送或读取响应阶段，连接 / 解码 / 响应体等类别；能获取时记录固定 I/O 类别与数字 OS 错误码 |
| 导航与状态 | 来源 / 目标的闭集分类、独立查询确认的 online 布尔值；未知仍为未知 |
| Browser 后端 | 受控 Rust HTTP 转发的同级请求 / 失败记录，另含主文档上下文与认证阶段 |

Browser 认证请求由 Rust 受控转发，使用同一 HTTP 细分；浏览器进程启动和私有管道异常仍按原有固定分类记录。本功能不是 Chromium 内部网络抓包或 HAR。Python CLI 的现有日志和底层 `--debug` 不受此开关管理。

## 如何读这次错误

`reason=network` 与 `reason=redirect_blocked` 含义不同：前者需要继续看网络事件，后者表示地址 / 跳转边界拒绝。网络事件的 `failure.phase=send` 与 `read_body` 区分请求发送和读取响应；`io_class`、`os_code` 可能为空，不能从 `connect` 单独断言 DNS、TLS、代理或防火墙根因。字段位于 JSONL 的 `data.record.failure`。

`phase=user_online` 是桌面外层任务标记，具体失败阶段以 `diagnostic.stage` 和阶段事件为准。登录若停在 `portal_navigation`，不能声称已经提交密码或调用 userOnline；退出若停在外层 verification，也不能推定此前没有执行下线。

## 资料边界

事件不记录用户名、密码、实际设备地址、Cookie、Authorization、原始 URL / query 值、票据、配置、页面、请求体或响应正文。错误只取枚举和数字，不拼接底层异常文本。文件仍包含操作时间和运行元数据，反馈前按[脱敏清单](security.md#公开反馈的脱敏清单)人工检查，只提供相关片段；不要附上配置目录或 Python 原始调试文件。
