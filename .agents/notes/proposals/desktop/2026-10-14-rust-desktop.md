# Tauri 全 Rust 图形版与素净界面

- 日期：2026-10-14
- 状态：已实施，开发分支 `feat/rust-desktop`；未发布，平台与校内验收边界见本轮证据。
- 范围：桌面认证、配置与后台生命周期、前端设计、构建验证；保留 Shell/Python 命令行版。

## 背景与替代关系

用户明确要求图形版使用 Tauri + 全 Rust 认证，在新分支开发，并重新参考 Figma 与优秀软件的设置页，视觉素净柔和。产品只分命令行版和图形版，Windows / Linux / macOS 是图形版的平台目标。

本决定替代此前 Python 旁车方案中桌面复用 Python 引擎和 JSONL 进程的部分（旁车与 Qt 源码已于 2026-10-18 移除）。此前的认证独立核验、未知状态、切换恢复、演示隔离、窗口与后台分离原则继续有效；此前安装包和测试不作为新 Rust 实现的成绩。

## 选择与边界

- Svelte 保留为共用界面，Tauri/Rust 负责桌面生命周期、认证与后台运行；图形版不启动 Python、Node 或 PyInstaller 认证旁车。
- Rust 认证实现放在独立库 `desktop/crates/ysu-auth/`，以现有协议和测试为行为证据，使用成熟 HTTP、HTML 与密码学组件；不在 UI 中重新实现认证。
- 原生运行管理保留版本化快照、串行认证操作、配置短时写锁和运行互斥；登录结果必须独立查询验证，未知状态不触发自动登录。发布序列另设互斥，回调前释放状态锁：Tauri 菜单调用同步等待主线程，而主线程也会读取快照，二者共持状态锁会死锁。
- 一次用户认证操作或自动重连的查询、变更与追加核验共享总超时，不把多个各自限时的库调用累加成更长操作。超时保持未知；账户读取超时不改连接状态。
- 需交互结果按账号、密码、运营商和后端组合暂停自动登录，与 Python 守护一致；改重试间隔、TLS 等设置不解除暂停。自动登录前仍比较完整最新配置，避免把暂停身份规则误当配置一致性规则。
- 原 Shell/Python 代码与运行方式保持兼容，不为本次图形版迁移改写稳定命令行产品。两种语言的协议实现通过相同输入、状态与失败分支测试约束，不能再声称它们共用同一份认证源码。
- 原 Qt 和 Python 旁车源码先保留作历史兼容，不再作为新图形版的构建或运行依赖；删除与正式退役另行确认。
- 原有用户配置路径、密码留空保留、偏好保存、互斥和外部管理语义延续；演示完全隔离，不继承用户凭据环境。
- 浏览器认证若使用系统 Chromium，由 Rust 直接控制专用临时会话；不依赖 Python/Playwright/Node，不复用用户浏览器资料。验证码与风控保持需人工处理的独立状态。

## 视觉取舍

素净柔和不等于降低文字对比度。2026-10-14 后续根据用户反馈，视觉从大圆角工作面和纵向设置表单进一步调整为纸白无框画布、轻灰侧栏、突出连接结论与并排的连接控制；字重、留白和轻分隔组织层级，取代同等权重的分区。只保留操作、动态状态、错误和关键约束，不添加占位说明文案。配色与布局由下述设计记录唯一维护。

Figma 资源和实际软件截图按真实可访问范围记录；页面返回 403 时，不声称已读取设计画布。具体来源、颜色/字体/布局与截图验证由[设计记录](../../../../docs/rust-desktop-design.md)维护。

## 已考虑的替代方案

- 继续 Python 旁车：已有实现和离线证据，但不符合本次全 Rust 图形版要求，退出当前桌面路线。
- 同时改写 Shell 版：扩大稳定命令行和部署风险，本次保留兼容。
- 三个平台各写一套界面：增加视觉和行为同步成本，继续共用前端与原生壳，平台差异集中适配。

## 后果与验证要求

新增 Rust 协议实现需要独立验证 CAS、Portal、cookie/XSRF、加密、服务核验、账户缺失值、超时和取消，避免仅对演示模式测试。全进程树验收应确认认证运行中也没有 Python/Node 依赖；包体积与内存分别测量。

当前主机可进行 Linux 构建、隔离的本地协议测试、浏览器预览和离线原生测试。Windows/macOS 构建、真实托盘/登录自启、校内 API/浏览器认证、签名与升级回退必须单独记录；未执行项保持待验。
