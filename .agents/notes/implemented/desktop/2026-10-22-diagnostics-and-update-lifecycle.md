# 固定诊断、复合刷新与签名更新生命周期

日期：2026-10-22<br>
状态：候选已实施，真实新机认证与远端更新待复验<br>
范围：Rust 原生桌面、共享 Portal 节点校验的 Python API / browser 镜像；不更改凭据覆盖、TLS 信任与 Portal 变更授权

## 背景

另一台 Windows 的 0.2.0 API 新登录失败；账号改正后公共提示从操作未核验变为查询失败。环境诊断和浏览器门户可用并不能定位原生会话失败；既有桌面仅按 code 输出公共文案，丢失了固定失败阶段。账户页 Info 独立读取了在线证据，却没有更新全局连接状态，外部下线后可出现账户与连接标记矛盾。此前真实验收仅覆盖既有在线会话读取，不支持宣称新登录已通过。

用户另要求在线更新。认证后台不依赖窗口存活，单看前端 busy 或瞬时快照不足以防止安装和排队 / 自动认证相交。

## 选择

- `AuthDiagnostic` 仅包含固定 operation / stage / reason 枚举，保留原 code / message 的库接口语义；桌面只消费枚举，未知构造回退 unknown，不显示任意 message、响应、URL 或账号。错误分类不凭字符串猜 DNS / TLS。
- 账户刷新改为 Info 后独立 Status，二段共用一个 Runtime 总预算。账户失败而独立状态在线仍保留在线；状态未核验则未知，不从账户数据推断连接。局部替代 [2026-10-15 托盘决策](2026-10-15-tray-control.md) 中 Info 仅改账户数据的语义，其余状态投影和线程约束保留。
- Portal 流程节点验证外 / 内业务信封，失败后禁止发 serviceLogin / userOnline；Python 两后端复用同一个校验函数和共享夹具。不是本次新机根因认定。
- 在线更新用官方插件、固定仓库 feed、内嵌公钥和 signed-version 绑定。用户确认后才下载安装；验签前不停止认证，不开放前端任意源 / 公钥或 guest updater 权限。普通构建无密钥，显式签名构建与 tag 发布要求签名。
- Runtime 的短工作门闩与所有认证工作入口线性化：有 active / busy 即阻止安装；idle 时置 updating / stop，后续启动、排队和自动任务不能起网络。无锁跨 await，不发送 Portal logout，也不持久关闭自动重连偏好。
- Bridge 序列化新请求与停机 / 恢复，安装失败用原配置重建后台；新快照 sequence 高于旧后台最终值，防前端把恢复事件当旧事件丢弃。恢复失败保持阻塞，显式恢复或退出，不自动无限重试。
- 安装准入、手工恢复准入与普通退出共用短退出门闩；安装 / 重建临界段不接受普通退出，下载期间仍可退出。官方 Windows `on_before_exit` 在启动安装器之前执行且启动仍可能失败，因此不用它提前清锁或丢失启动上下文；成功安装走插件自己的进程退出。
- 管理给 Tauri 的重启 Env 使用已解析的绝对配置参数并保留最小化 / 模拟等旗标；不依赖升级后的工作目录，也不把凭据放进启动参数。

## 备选与限制

直接输出底层异常可缩短排障，但含身份或会话的 URL / 服务器文本不能进入公共日志。只按 code 输出又失去定位价值，故选择固定枚举。删除账号匹配或放宽 HTTP / 可信来源只会掩盖根因，本轮未采用。

账户结果直接覆盖 status 较省请求，但缺少完整账号 / 服务证据并存在读写竞态，故保留独立复查；代价是一次刷新多一次只读会话查询。未加入持续浏览器轮询或擅自启用自动重连来掩盖状态问题。

自制下载器 / 验签和仅检查 busy 后强制退出均被放弃：前者增加密码学维护面，后者不能覆盖配置加载和排队窗口。安装前先停后台再下载会让网络 / 签名失败影响正常认证，故先下载验签、再短暂停机。

当前 Linux deb 仅手动更新，不以其他格式的框架能力冒充支持。Windows / macOS 发布者签名、公证与更新载荷签名不同。0.2.0 无更新入口，需要首次手动升级；现有 GitHub Release / Secret 未由本候选自动变更。
