# 首个正式更新信任锚与发布前验签

日期：2026-10-24<br>
状态：密钥保管、Secrets 与未发布公钥基线已配置；正式发布仍由完整 CI / 标签门槛决定<br>
范围：首次正式更新发行 v0.2.1 的信任锚、密钥保管、候选包迁移与发布前验证，不更改运行时更新授权和验签强度

## 背景

v0.2.1 尚无正式标签或 Release；v0.2.0 没有软件内更新入口。旧候选源码已有内嵌公钥，但原私钥未登记具体位置，仓库 Actions Secrets 为空，在已核对的项目专用位置也未找到原文件；这不等于证明原密钥已被销毁。用户在得知公钥变更与候选包手动重装的后果后，明确批准为首次正式版建立新签名密钥。

发布资产装配的签名结构、版本字段及 SHA 校验不能证明实际载荷受客户端公钥信任。当前 Tauri CLI 2.12.2 为支持轮换，在签名 key ID 不匹配时可能只告警而继续，故构建成功也不构成该证明。

## 选择

- 使用官方 Tauri signer 建立首个正式更新密钥；只更新尚未正式发行的 0.2.1 内嵌公钥，不覆盖原文件、不声称可从旧公钥推导私钥。该项补充[原更新生命周期决策](2026-10-22-diagnostics-and-update-lifecycle.md)，其确认授权、下载后验签、后台停机 / 恢复和锁语义继续有效。
- 私钥与公开配对文件保存在用户数据目录的专用 `ysu-net-signing/v0.2.1-release-20261024/` 中，目录 0700、文件 0600；另保存无秘密值的文件定位与公钥摘要元数据。当前本机私钥无口令，依赖所有者访问保护，远端采用 GitHub Actions Secrets 加密保管；应由所有者另做安全备份，不经聊天、源码、日志或构建附件传递。工具可能输出密钥的标准输出直接抑制或私有暂存后丢弃，不作为验收日志保留。
- 通过标准输入把私钥安全配置到此仓库的 `TAURI_SIGNING_PRIVATE_KEY` Secret，不把私钥值作为命令参数或聊天工具参数。公钥文件 SHA256 为 `57de1a2962b7535c52a720912ad2b3d8c3823908e766a085481c8f6ef14ce3c9`；这里只记录公开摘要，不记录私钥或口令。
- 发布作业使用维护中的 Minisign 校验三个实际更新载荷及覆盖备注的全局签名，随后核对精确受保护版本；输入来自客户端配置中的原定信任锚，不从同一批待发布附件下载公钥自证。清单目标、固定 URL、内联签名、全部资产与摘要同时通过才允许发布。没有验证工具、错误密钥或损坏载荷都须失败。

## 后果与替代方案

保留旧公钥等待原私钥最能兼容候选安装包，但目前没有可用的原文件位置，正式签名无法继续；用户没有选择该路径。静默换钥并期待旧候选自动升级会破坏已安装候选的信任，故明确要求旧 0.2.1 候选用户手动安装正式版并重启。v0.2.0 首次升级本来就需手动安装；该决策不是未来正式版任意换钥的许可，首次正式发布之后必须维护本密钥或另行设计迁移。

关闭验签、改成信任远端任意公钥、复用测试私钥或以普通安装包冒充签名更新均被拒绝。更新载荷签名仍不等于 Authenticode 或 Apple 发布者签名 / 公证。
