# 托盘状态投影与后台入口

日期：2026-10-15  
状态：已实施，验收结果单列于本轮记录  
范围：Tauri 桌面共用代码及 Linux 托盘宿主生命周期；不变更 CLI/Qt 兼容版

## 背景

主窗口关闭后，原菜单只有连接状态和少量操作，缺少账号、IP、额度及最近结果。核心发布快照时仍持有 publication 锁，而原生菜单 API 可同步等待主线程；把复杂菜单更新直接放在快照接收路径，会扩大锁重入和跨线程等待的风险。

## 选择

- 用纯数据 TrayView 从核心快照投影菜单、图标角标和悬停摘要；不另建认证、重连或轮换实现。未知连接状态只查询；忙碌时保留停止已有自动化与退出的入口。
- 快照接收方仅短暂持有更新队列锁，合并最高 sequence 并调度主线程。原生 API 调用时不持有核心状态、发布锁或托盘更新锁；应用成功后才记录已应用模型，失败保留重试机会。每个主线程回调只应用一版，后续更新另排，避免持续发布占满窗口事件循环。
- 构建托盘后主动投影当前快照，覆盖首次快照早于菜单安装的启动顺序。操作结束强制恢复权威勾选值，覆盖原生勾选项先行切换及写入失败。
- 刷新按同一核心队列先查询状态、再读取账户；Info 本身不改变连接状态。额度只显示同账号/运营商已核验账户的上次查询值，不宣称实时计费。
- Windows 摘要限制为 127 UTF-16 单元，各字段分别限长，保留自动化状态。Windows 菜单文字转义助记符 &。Linux 跳过不受支持的 tooltip 设置及图标鼠标事件，使用完整菜单提供入口。
- Linux 每十秒在阻塞工作线程查询托盘宿主，宿主消失时调度主线程恢复窗口。此探测只访问会话 D-Bus，不查询校园网；重新聚焦窗口时更新桌面能力。

## 考虑过的替代方案

在核心回调中逐项设置菜单改动少，但保留 publication 与主线程同步等待的交叉风险。由前端接管托盘状态会让关闭 WebView 后的功能依赖已销毁页面。用悬浮 WebView 替代原生提示会增加窗口生命周期、定位、焦点和平台差异，当前信息量使用原生摘要加菜单即可。

## 后果与限制

正常 D-Bus 响应下，Linux 托盘宿主恢复窗口约延迟一个探测周期；总延迟还包括会话总线调用和主线程排队。D-Bus 异常按宿主缺席处理。菜单 setter 失败可能出现短暂的部分更新，下个快照或强制刷新重试，不把部分更新当已应用。Windows/macOS 共用实现不等于已在真实系统验证；Linux 的受控 D-Bus watcher 和 GTK 菜单截图也不等于真实面板鼠标测试。
