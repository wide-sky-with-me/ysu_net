# 更新缓存锁随所有者释放

日期：2026-10-28。状态：开发源码已实施，云端复测待执行。范围：三平台更新缓存生命周期；延续[签名差分决策](2026-10-25-signed-delta-download.md)，不改变签名、缓存目录或下载回退边界。

## 证据与选择

0.2.3 候选 153f24c 的 macOS arm64 原生回归中，首次整包下载完成后立即重新打开缓存，得到 WouldBlock；同一测试在前一候选四平台通过。缓存原来只依靠 File drop 关闭描述符来释放 flock。Unix 并行启动子进程时，即使设置 CLOEXEC，fork 至 exec 的短窗口仍可能持有相同打开文件描述，延长锁寿命；这是与并行新进程测试及文件锁语义相符的解释，未抓取当时 fork 事件，不能宣称其已被直接观察。

为 Cache 增加 Drop，先显式解锁，后由字段关闭描述符。所有者的完整下载、基线读取、验签及维护期间仍持有独占锁；析构之后不允许继承描述符延长占用。Windows 使用同一 fs2 解锁接口，保留原 no-delete-share 目录与对象身份检查。

未选择加重试或串行化整套测试，因为这不能保证所有者释放合同；未选择移除排他锁或 CLOEXEC，因为原并发和句柄继承边界仍必要。析构不能返回错误，解锁错误保留原文件关闭兜底，不引入自动安装或网络重试。

## 实现与验证

实现：[updater_delta.rs](../../../../desktop/src-tauri/src/updater_delta.rs)。[回归](../../../../desktop/src-tauri/src/updater_delta_tests.rs)在 Unix 用 try_clone 重建共享文件描述：所有者存活时拒绝第二个缓存，所有者销毁后即使克隆仍在也可重新取得锁，旧克隆关闭不会解除新所有者的锁。原首次下载 / 缓存断言保留，没有跳过或放宽。
