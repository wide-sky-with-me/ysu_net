# 用真实 Shell 换号合同约束 Rust 编排与诊断

日期：2026-10-28。状态：Shell 双账号实测完成；Rust 诊断及回归源码已实施，云端格式 / 编译 / 执行待进行。用户要求当前只保留源码。

范围：共用 Rust Worker 账号切换诊断及其测试，不更改账号簿格式、自动触发、认证算法或生命周期锁。当前规则唯一维护在[多账号说明](../../../../docs/accounts.md)，当次证据归[21 实测](../../../../docs/account-pool-21-review-2026-10-28.md)。

## 背景与选择

用户要求先验证 Shell，再改进 Rust，并强调先退出旧账号、再登录新账号。正式 v0.2.2 Shell 在 21 的移动 A / 校园网 B 间，直接切换和守护持锁热切换各双向一次，均取得真实 offline → 新 CAS → 新身份在线 → 提交活动配置的证据。没有强造坏密码或零流量，不将这些成功当作真实失败恢复或自动触发已通过。

Rust 已有相同的核心动作顺序及共同总预算。保留这些条件，补全每阶段的 phase，避免总超时被记录在 Queue；对下线和目标登录的 AuthError 调用已有固定分类日志，保留 PortalNavigation / RedirectBlocked 等根因，即使后续状态查询或恢复成功也不丢失历史错误。原服务原文仍不进入公开日志。

测试在实际 Worker / Store 上加入仅 cfg(test) 的调用事件、指定查询门闩和指定查询失败。用门闩停在目标独立核验，直接检查磁盘配置仍为原账号；随后释放才可提交。另一反例让目标已实际在线但核验失败，必须退出目标、恢复原账号且保留原活动配置。这些测试记录行为和持久化时点，不能由计数器或动作返回成功替代。

## 实际考虑的替代方案

- 重写另一套 Rust / Python 换号算法：已有真实 Worker 可测，重复实现会分叉，未采用。
- 把通用失败消息当作足够诊断：会抹掉底层 DNS / TLS / 跳转 / CAS 分类，不利于 Windows 现场定位，改为复用原固定分类日志。
- 为测试故障在真实校园网故意提交错误密码、制造流量耗尽：本次不需要；真实只做有效账号正向切换，失败及提交时序由可控后端验证。
- 自动把状态未知当作离线、提前写目标配置或扩大恢复重试：与已验证合同不符，未采用；原身份、并发意图和冷却约束继续有效。

本决定补充[原账号轮换设计](../../proposals/accounts/2026-10-14-account-rotation.md)，不取代其默认关闭、双次零报告、保存兼容或恢复边界。
